## 1. 产品概述

**一句话**：记录宝宝每天吃的辅食，按月龄查带图片的做法教程，未来在同一个入口卖自制辅食。

| 项 | 说明 |
|---|---|
| 目标用户 | 主用户：你（运营者 + 喂养记录者）；次用户：其他宝妈（浏览教程） |
| 核心场景 | ① 喂完辅食拍照记录；② 按月龄找做法；③ 你从小红书整理教程发布给所有用户看 |
| 形态 | 微信原生小程序（现有初版工程增量改造） |
| 角色 | 访客（未登录）/ 登录用户 / 运营者 |

### 1.1 角色权限矩阵

| 能力 | 访客 | 登录用户 | 运营者 |
|---|---|---|---|
| 浏览教程库、教程详情 | ✅ | ✅ | ✅ |
| 浏览小店、商品详情 | ✅ | ✅ | ✅ |
| 查看/新增/编辑/删除喂养记录 | ❌（引导登录） | ✅ 仅自己的 | ✅ 仅自己的 |
| 上传记录图片 | ❌ | ✅ | ✅ |
| 发布/编辑/下架教程 | ❌ | ❌ | ✅ |
| 设置宝宝档案 | ❌（引导登录） | ✅ 仅自己的 | ✅ 仅自己的 |

> 运营者身份 = 其登录邮箱在 `operator_whitelist` 白名单中。白名单由数据库维护（初期由我手动写入你的邮箱）。

## 3. 详细需求

### 3.1 FR-01/18/19 首页（Tab 1）+ FR-02/03/04 喂养记录

**首页定位**：打开即看「今天吃了什么 + 给宝宝做什么」的聚合页，记录流水账收纳到二级页。

**首页结构（自上而下）**

① **今日概览区（FR-01）**
- 展示**最近一天**的记录（今天有记录显示今天；今天还没记则显示最近有记录的那天，并在顶部标注日期，如「11月2日 · 周一」）
- 该天记录按餐次排序展示：餐次 + 辅食名 + 反应标签 + 缩略图（有图时）
- 区块右上角「查看全部 >」进入完整记录列表页（FR-19）
- 底部常驻「+ 记一笔」快捷按钮，唤起新增表单
- 空状态（从未记录）：插画 + 「记录宝宝的每一口辅食」+ 立即记录按钮

② **推荐辅食区（FR-18）**
- 标题：「给宝宝推荐」/ 已设档案时显示「适合{宝宝小名}（X月龄）」
- 推荐逻辑（按优先级）：
  1. 已设宝宝档案 → 从**宝宝当前月龄段**的教程中推荐 6 道（云端运营者发布优先、其余内置教程随机）
  2. 未设档案 → 默认展示「本月龄热门精选」（内置教程中随机 6 道），并提示「设置宝宝月龄，推荐更精准 >」跳转档案设置
- 卡片：封面图 4:3 + 名称 + 月龄标签，两列网格或横向滑动（开发时按现版工程风格定）
- 「换一换」文字按钮：随机刷新一批
- 点击卡片 → 教程详情页
- 无推荐数据（云端无发布且内置为空）时该区隐藏

**FR-19 完整记录列表页**
- 从首页进入，展示全部记录：按日期倒序分组（日期吸顶），组内按餐次排序
- 交互与原记录列表一致：点卡片编辑、删除二次确认、右下角「+」新增
- 空状态同首页

**FR-02/03/04 新增/编辑/删除/图片预览**（交互规则不变，从首页或列表页均可唤起）

**新增/编辑（底部弹层）**

| 字段 | 类型 | 必填 | 规则 |
|---|---|---|---|
| 日期 | 日期选择器 | ✅ | 默认今天，不可选未来日期 |
| 辅食名称 | 文本输入 | ✅ | 1-20 字；可从教程库选填（选填后自动带名称） |
| 餐次 | 单选 | ✅ | 早餐/午餐/晚餐/加餐，默认「午餐」 |
| 反应 | 单选 | ✅ | 爱吃/一般/不爱吃/过敏，默认「一般」 |
| **图片** | 上传 | ❌ | **最多 3 张**，见 3.1.1 |
| 备注 | 多行文本 | ❌ | ≤100 字 |

**3.1.1 图片上传规则（新增需求 D8）**
1. 入口：`wx.chooseMedia`（mediaType: image，sourceType: 相册 + 拍照，count: 剩余可选数）
2. 上限 3 张；达到上限时「+」置灰并提示「最多 3 张」
3. 选择后前端压缩：`sizeType: compressed`，单张目标 ≤500KB、长边 ≤1280px
4. 上传至云文件存储，路径规则：`records/{用户id}/{记录id或临时id}/{时间戳}.jpg`
5. 上传中：缩略图显示进度遮罩；失败：该图显示「重试」角标，可单独重传
6. 删除：图片右上角「×」，仅删除本地待上传项；已保存记录中删图 = 保存时提交新数组（旧文件由云端定时清理或保留，不做同步删除）
7. 点击缩略图：`wx.previewImage` 全屏预览，支持左右滑动、保存到相册
8. 记录保存顺序：先传图片拿到 URL 数组 → 再写入记录 → 任一步失败给出明确 toast，不静默失败
9. 权限被拒（相册/相机）时：提示「需要相册权限才能添加图片」，并提供「去设置」入口

**编辑/删除**
- 点击卡片进入编辑（表单回填，含已有图片）
- 删除：`wx.showModal` 二次确认「删除后不可恢复，是否继续？」

**验收标准**
- 断网时新增记录：提示失败并保留表单内容，不丢失用户已填内容
- 上传 2 张图成功保存后，杀进程重进，图片仍可显示（云端 URL 持久）
- 非本人记录不可见、不可改
- 今天记录后首页今日概览立即更新；隔天打开首页自动显示最近有记录的一天
- 已设宝宝月龄 8 个月 → 推荐区只出现「7-8月龄」或相邻可过渡月龄的教程
- 「换一换」点击后推荐批次刷新且不与上一批完全重复（内置教程充足时）

### 3.2 FR-05/06/07 教程库

**列表页**
- 顶部横向月龄标签：全部 / 6月龄 / 7-8月龄 / 9-11月龄 / 12-24月龄（默认「全部」；若已设置宝宝档案，默认选中宝宝当前月龄段并高亮提示「已按宝宝月龄筛选」）
- 搜索框：按教程名 / 食材 / 标签模糊搜索，输入即筛（防抖 300ms）
- 卡片：**封面图 4:3** + 名称 + 月龄标签 + 2-3 个特性标签；图片 `lazy-load`
- 数据来源：内置 36 道（本地）+ 运营者发布（云端）合并展示，云端数据在前、按发布时间倒序
- 空状态：搜索无结果时提示「没找到，换个关键词试试」+ 清除筛选

**详情页**
- 顶部：封面大图（可点开预览）
- 标题区：名称 + 月龄 + 标签 + 来源行（见 3.3.3）
- 食材清单：列表式，含用量
- 分步做法：步骤序号 + 文字（V1 步骤不配图；数据结构预留 `stepImages`）
- 小贴士：带图标的高亮块，安全相关文案加粗（如「1 岁前不加盐糖」）
- 底部安全提示固定文案：「首次添加新食材请少量尝试，观察 3 天是否过敏」

### 3.3 FR-08/09/10 运营者

**3.3.1 登录**
- 方式：邮箱验证码（`cloud.auth` 邮箱 OTP）
- 流程：输入邮箱 → 发送验证码（60 秒倒计时）→ 输入 6 位码 → 登录成功
- 登录态持久化，冷启动自动恢复；退出登录需二次确认
- 登录入口：「我的」页顶部；运营者在「教程」页额外看到「+ 发布教程」悬浮按钮

**3.3.2 发布教程**

| 字段 | 必填 | 规则 |
|---|---|---|
| 教程名称 | ✅ | ≤20 字 |
| 适合月龄 | ✅ | 四档单选 |
| 封面图 | ✅ | 1 张，相册/拍照或使用内置图，上传云存储 |
| 食材清单 | ✅ | 动态增删行（名称 + 用量），至少 1 行 |
| 做法步骤 | ✅ | 动态增删行，至少 1 步，每步 ≤100 字 |
| 小贴士 | ❌ | ≤100 字 |
| 标签 | ❌ | 最多 3 个，从预设标签选（补铁/补钙/蔬菜/水果/肉类/泥糊/颗粒/手指食物/易消化） |
| 来源说明 | ❌ | 选填，≤30 字，见 3.3.3 |

- 提交后立即发布，全用户可见（无需审核）
- 我的发布列表：可编辑、下架（下架后不再对用户展示，数据保留）
- 内置 36 道教程不可编辑/删除

**3.3.3 来源标注规则（回应 D-问题3）**
- **选填**，不做强制校验
- 占位提示：「整理自小红书 @作者名（选填）」
- 详情页来源行仅在填写时展示；为空时展示「本站整理」
- 表单底部固定提示文案：「建议用自己的话重新整理做法，避免大段复制他人原文与图片」

**3.3.4 PC 网页管理后台（FR-17，新增）**
- 独立 Web 页面（浏览器访问），与小程序**共用同一云环境**：同一数据库、同一 `operator_whitelist` 邮箱白名单，登录方式同为邮箱验证码
- 功能：教程列表（含内置/发布/下架状态）、新建/编辑/删除教程、上传封面图（压缩规则同 §6）、发布/下架切换
- 边界：不做对客展示页；不管理喂养记录（记录是用户隐私数据，仅小程序端可见）；表单字段与 3.3.2 完全一致
- 价值：PC 端打字、批量录入、上传图片比手机高效，适合日常内容运营主阵地；小程序端发布作为移动补充保留

## 5. 数据结构

### 5.1 云端表（需开通云服务）

| 表 | 字段 | 权限（RLS） |
|---|---|---|
| `food_records` | id, owner_id(default auth.uid()), date, food, meal, reaction, images(text[]), note, created_at, updated_at | 本人读写 |
| `baby_profiles` | id, owner_id, nickname, gender, birthday, updated_at | 本人读写（1 人 1 条） |
| `tutorials` | id, owner_id, owner_name, title, age_month, cover_url, ingredients(jsonb), steps(jsonb), tips, tags(text[]), source_note, status(published/offline), created_at | **公开可读（status=published）**，仅运营者可写 |
| `operator_whitelist` | email(pk), note, created_at | 仅运营者可读（写入由后台/我手动执行） |

### 5.2 本地内置数据

| 文件 | 内容 |
|---|---|
| `data/recipes.js` | 36 道内置教程（名称/月龄/封面路径/食材/步骤/贴士/标签/来源） |
| `assets/recipes/*.jpg` | 36 张 AI 生成封面图（压缩后 ≤60KB/张，总 ≤2MB，放分包） |

### 5.3 存储与体积约束

- 小程序单包 ≤2MB，分包单个 ≤2MB，总体积 ≤20MB
- 封面图：640×480、JPEG 质量 70、目标 40-60KB/张 → 36 张约 1.5-2.2MB，**必须放分包**，主包只保留首屏必需资源
- 用户记录图片不打包，全部走云端 URL

## 6. 图片素材规范（D6 混合方案）

**AI 生成封面（V1 先上）**
- 视角 45° 俯拍、白瓷碗/木碗、浅木桌面 + 米白棉麻、柔和暖光、背景虚化
- 碗占画面 60-70%，可点缀新鲜原材；禁止文字、人手、品牌标识
- 成品性状必须符合月龄（泥糊 / 细颗粒 / 手指食物）
- 右下角平台「AI生成」水印保留（合规友好），不做去除

**后续真实替换**
- 替换时仅改图片文件或 `cover_url`，页面代码不动
- 实拍同样遵守上述构图与光线规范，保证列表整齐

**记录图片（用户上传）**
- 单张 ≤500KB、长边 ≤1280px、jpg
- 用户可见提示：「图片仅用于你自己的记录，请避免上传宝宝正脸等敏感信息」

## 7. 非功能需求

| 项 | 要求 |
|---|---|
| 性能 | 首页首屏 ≤1.5s（弱网 ≤3s）；列表图片懒加载；分页每次 20 条 |
| 体积 | 主包 ≤2MB（教程封面走分包） |
| 三态 | 所有数据页具备 loading / empty / error（error 带重试） |
| 错误提示 | 网络失败、未登录、无权限、上传失败均给明确中文提示，不静默失败 |
| 隐私合规 | 小程序「用户隐私保护指引」需声明：相册/摄像头（上传图片）、邮箱（登录）；`wx.chooseMedia` 前走隐私授权 |
| 数据隔离 | 记录与档案按 owner_id 隔离，前端不传 owner_id |
| 弱网 | 上传支持失败重试，记录保存失败不清空表单 |
