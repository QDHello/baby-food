## 2. 详细需求

### 2.1 FR-20 食谱收藏 / 取消收藏（食谱详情页）

- 详情页导航栏（或标题区）新增**心形按钮**：未收藏 = 空心 + 灰色描边；已收藏 = 实心 + 主色 `#52C41A`
- 点击切换收藏态，toast 反馈：「已收藏」/「已取消收藏」（icon: none，短暂）
- 收藏即时落盘（storage），无需保存按钮
- 已收藏再次进入详情页，按钮显示实心态
- 删除收藏无二次确认（可随时再收藏，低风险操作）

### 2.2 FR-21 我的收藏列表页

- 入口：「我的」页新增「我的收藏」行（心形图标 + 数量角标，如「我的收藏 · 8」）
- 列表：按**收藏时间倒序**，卡片复用食谱列表样式（emoji/封面 + 名称 + 月龄标签），点击进详情页
- 卡片右侧「已收藏」实心心形，点击直接取消收藏并从列表移除（带 200ms 淡出动画可选）
- 空状态：「还没有收藏的食谱，去食谱库逛逛吧」+ 按钮跳食谱列表页
- 数据隔离：与喂养记录一致，按当前宝宝维度存取；未设宝宝档案时收藏不可用（入口置灰 + 提示「请先添加宝宝档案」）
- 切换宝宝后收藏列表随之切换（各宝宝收藏互不可见）

### 2.3 FR-22 食谱列表收藏角标（P2，可选）

- 食谱列表页、首页推荐卡片上：已收藏的食谱显示右上角小实心心形角标（主色）
- 仅做标识，不可点击收藏（收藏动作只在详情页发生，避免误触）

### 2.4 FR-23/24/25/26 喂养统计页

- 入口：「我的」页新增「喂养统计」行（柱状图图标）
- 页面结构（自上而下）：

**① 概览卡（FR-23）**：三格横排

| 指标   | 口径              |
| ---- | --------------- |
| 累计记录 | 当前宝宝全部喂养记录条数    |
| 打卡天数 | 去重后的有记录天数       |
| 尝试食谱 | 去重后的食谱数（含自定义食谱） |

**② 反应分布（FR-24）**：三行横向条形（纯 CSS，宽度 = 占比），无（绿）/ 过敏（红）/ 不适（橙），每行显示次数；全部为「无」时展示「目前所有记录反应良好 👍」替代图表

**③ 过敏关注（FR-25）**：

- 列出触发过「过敏」反应的食谱，按过敏次数倒序（食谱名 + 次数 + 最近一次日期）
- 底部固定提示：「以上食谱曾引发过敏反应，再次添加前建议咨询医生；如需排查请在宝宝档案中勾选对应过敏原」
- 无过敏记录时本区块隐藏

**④ 近 30 天打卡热度（FR-26）**：30 根细条形图（纯 CSS flex 布局），高度 = 当日记录数，hover/长按显示「X月X日 · N条」（简单实现：下方仅标注每周一的日期刻度）

**⑤ 最常做食谱 Top5（FR-26）**：按记录条数倒序，显示名称 + 次数 + 排名徽标（🥇🥈🥉 + 4/5）

- 统计范围切换：默认「全部」；顶部提供「本月 / 全部」分段切换（本月 = 当前自然月）
- 数据全量从 `feeding.getLogs(babyId)` 现算（数据量 <数千条，无需预聚合）；无记录时整页显示空状态「记下第一口辅食，统计才有内容」+ 立即记录按钮
- 统计页不可编辑，纯只读；页面使用默认导航栏（返回）

**验收标准（统计）**

- [ ] 三格概览数字与记录列表逐条核对一致（新增/删除记录后返回统计页数字联动）
- [ ] 打卡天数 = 记录中不重复日期数；一天多条只算 1 天
- [ ] 反应分布三色与全局语义色一致（无绿 / 过敏红 / 不适橙）
- [ ] 过敏关注列出全部触发过敏的食谱，次数正确，无过敏记录时区块不出现
- [ ] 30 天热度图含今天，无记录日为空条；「本月」切换后数据范围正确
- [ ] 未设宝宝档案进入统计页显示引导空态，不报错

**验收标准（收藏）**

- [ ] 详情页收藏后，我的收藏列表立即可见且排序正确
- [ ] 取消收藏（详情页或列表页）后列表实时移除；再次收藏回到列表（时间更新）
- [ ] 杀进程重进收藏不丢失（storage 持久化）
- [ ] 切换宝宝后收藏列表正确隔离，无串数据
- [ ] 未设宝宝档案时入口置灰并有引导提示

## 3. 交互与视觉约定

- 全部沿用现有体系：主色 `#52C41A`、卡片白底圆角 24rpx、页面底 `#F5F5F5`；统计条形图配色：绿 `#52C41A` / 红 `#e53935` / 橙 `#FFA726`
- 收藏心形：选中态实心主色，未选中空心描边 `#bbb`
- 页面均在 `app.json` 注册（收藏列表、统计页均为普通页面，非 tabBar）
- 三态（loading/empty/error）遵循全局约定；本期纯本地无 error 态场景，实现 empty 即可

## 4. 数据结构（本地 storage，阶段 2 上云时映射云端表）

### 4.1 收藏 `babyfood_favorites_{babyId}`

```js
// Array<{ id: string, createdAt: number }>，按 createdAt 倒序使用
[{ "id": "r12", "createdAt": 1762665600000 }]
```

- `id` = 食谱 id（`RECIPES` 中的 `id` 字段）
- 阶段 2 云表 `baby_favorites`：id, owner_id, baby_id, recipe_id, created_at（RLS 本人读写）

### 4.2 统计

不新增存储，全部从既有 `feeding` 服务（`getLogs(babyId)`）实时聚合计算；聚合逻辑收敛在 `utils/stats.js`（新增），页面只消费指标。

## 6. 边界与本期不做

| 项        | 说明                                      |
| -------- | --------------------------------------- |
| 自定义食谱收藏  | 不做（D21）；二期后若需要，扩展 favorites 的 source 字段 |
