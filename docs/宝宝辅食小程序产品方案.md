## 1. 产品概述

| 项目   | 说明                                                      |
| ---- | ------------------------------------------------------- |
| 产品名称 | **蹦Food**（已注册）                                          |
| 定位   | 宝宝辅食记录工具 + 带图片的辅食教程库，运营者可发布教程给所有用户，后期扩展为自制辅食小店 |
| 目标用户 | 你（运营者 + 记录者）+ 浏览教程的宝妈用户 → 未来购买辅食的用户            |

## 3. 功能设计（V1 概要）

### 3.1 首页（Tab 1）· 今日概览 + 推荐辅食

**核心场景**：打开即看「今天吃了什么 + 给宝宝做什么」。

**① 今日概览区**
- 只展示**最近一天**的辅食记录（今天没记则显示最近有记录的那天，顶部标注日期）
- 每条记录：
  | 字段 | 说明 |
  | ---- | ---- |
  | 餐次 | 早餐 / 午餐 / 晚餐 / 加餐 |
  | 辅食名称 | 如「南瓜泥」 |
  | 反应 | 爱吃 😋 / 一般 😐 / 不爱吃 🙅 / 过敏 ⚠️（过敏红色标记） |
  | 图片 | 选填，最多 3 张，可预览 |
  | 备注 | 选填 |
- 「查看全部 >」进入完整记录时间线；「+ 记一笔」快捷唤起新增表单（字段：日期/名称/餐次/反应/图片/备注，详见 PRD §3.1）

**② 推荐辅食区**
- 已设宝宝档案 → 按宝宝当前月龄推荐 6 道教程（封面图卡片，「换一换」可刷新）
- 未设档案 → 默认精选 6 道 + 「设置宝宝月龄，推荐更精准」引导
- 点击进入教程详情

### 3.1a 完整记录列表页（二级页）

- 全部历史记录按日期倒序分组、日期吸顶；编辑/删除/新增交互同前
- 新增/编辑为底部弹层表单；删除二次确认

### 3.2 教程库（Tab 2）

- **初始内容**：已整理 36 道辅食教程（来自中国营养学会喂养指南、儿科科普等公开资料），按月龄分布：6 月龄 9 道、7-8 月龄 9 道、9-11 月龄 10 道、12-24 月龄 8 道；含食材用量、3-6 步做法、安全小贴士（1 岁前不加盐糖、排敏观察 3 天等）
- 顶部月龄筛选：全部 / 6月龄 / 7-8月龄 / 9-11月龄 / 12-24月龄
- 搜索框：按名称/食材/标签搜索
- 教程卡片：**成品封面大图** + 名称 + 月龄标签 + 特性标签（补铁/蔬菜/泥糊…）
- 详情页：顶部封面图 → 食材清单 → 分步做法 → 小贴士（安全提示高亮）
- **多媒体要求**：每道教程至少 1 张成品封面图；步骤图与视频 V1 不做（数据结构预留），后续按需加入
- 长期内容运营：见 §6

### 3.5 运营者角色 · 教程发布（V1，需求已确认）

**角色定义**：运营者 = 你（可以多个账号），拥有教程发布权；普通用户只浏览、不发布。

| 能力 | 说明 |
|---|---|
| 添加教程 | 运营者登录后，教程库出现「+ 添加教程」入口；表单字段与内置教程一致：名称 / 月龄 / 食材 / 步骤 / 小贴士 / 标签 / 来源标注 |
| 全用户可见 | 发布后进入公开教程库，与内置 36 道混排展示，所有用户无需登录即可浏览 |
| 管理 | 运营者可编辑、下架自己发布的教程；内置教程不可删 |
| 来源标注 | 选填字段，未填显示「本站整理」；引导改写而非照搬（详见 PRD §3.3.3） |
| PC 管理后台 | 浏览器打开的网页后台，教程增删改查 + 上传封面图，与小程序共用云数据库和邮箱白名单，日常内容运营主阵地 |

**权限实现**：云端教程表「公开可读、仅运营者可写」。运营者通过登录账号白名单识别（你把账号加进白名单即获得发布权，后续可增删运营者）。

**浏览是否需要登录**：建议**浏览免登录**（公开只读），只有「记录辅食」和「运营者发布」需要登录——降低普通用户使用门槛。

### 3.3 小店（Tab 3，V1 仅展示）

- 3 个示例商品（猪肝粉 / 果蔬小馒头 / 三文鱼小丸子，占位数据）
- 商品卡片列表（图片 + 名称 + 一句话描述 + 价格）
- **商品详情页底部按钮统一「敬请期待」**（灰色不可点，点击提示筹备中）；无购物车、无下单、无支付

### 3.4 我的（Tab 4）

- **宝宝档案**（1 个宝宝）：小名、性别、出生日期 → 自动计算并展示「X 个月 XX 天」，教程库据此默认筛选适合月龄
- 登录状态展示（邮箱验证码登录 / 退出）、我的发布（仅运营者）
- 关于/说明：版本信息、免责声明（教程仅作参考，添加新食材请注意排敏）

### 3.6 图片与视频方案（需求已确认）

**为什么必须认真设计**：教程"能不能看下去"很大程度取决于成品图。但小程序有硬性体积限制——**主包 ≤2MB、单个分包 ≤2MB、代码包总体积 ≤20MB**。36 道教程若每道 4 张图（约 150 张），图片放本地必然超限，视频更不可能打包。因此素材策略分三层：

| 素材层级 | 内容 | 存放方式 | 说明 |
|---|---|---|---|
| 列表封面 | 36 张成品图（每道 1 张，压缩至 40-60KB） | 本地分包 `assets/recipes`（总量控制在 2MB 内） | 卡片首屏秒开 |
| 步骤配图 | 后续按需 2-4 张/道 | 云存储 | 数据结构预留，暂不开发 |
| 做法视频 | **V1 不做**（无视频号） | 数据结构预留字段 | 后续可用云存储播放或开通视频号后跳转 |

**加载体验**：列表 `<image lazy-load>` 懒加载 + 统一 4:3 裁切；图片统一压缩规范（详见 PRD §6）。

**素材路径（已确认 C 混合）**：我批量生成 36 张成品示意图用于上线，你后续逐步用真实拍摄替换（只改图片文件/地址，页面不动）。
| 路径 | 优点 | 缺点 |
|---|---|---|
| A. AI 生成成品示意图 | 立刻可用、风格统一 | 是示意图非实拍，需标注 |
| B. 你自己拍/录 | 真实、最适合卖货转化 | 工作量最大 |
| **C. 混合（已选）** | 先 AI 后实拍，兼顾速度与可信度 | 需逐步替换 |

**已确认：采用路径 C（混合）** —— 我先批量生成 36 张成品示意图用于 V1 上线，你后续逐步用真实拍摄替换（替换时只改图片文件/云存储地址，页面不动）。

**统一风格规范（AI 生成与实拍都遵守，保证列表整齐）**：
- 视角：45° 俯拍，俯视微倾，主体居中
- 器皿：白色陶瓷小碗 / 木质辅食碗，不加花纹
- 背景：浅木纹桌面或米白棉麻桌布，虚化处理
- 光线：柔和自然光，暖色调，无强阴影
- 构图：碗占画面 60-70%，旁边可点缀新鲜食材原材一小份
- 禁止：文字水印、人手、品牌标识、夸张滤镜；成品状态要符合该月龄可食用性状（泥糊/颗粒/手指食物）

> 版权：公开传播场景下不要直接使用小红书/他人图片视频。要么 AI 生成、要么自己实拍，若要引用他人素材需获得授权或仅放来源链接。


## 4. 数据结构

**云端表（V1 即上云，权限由数据库层强制）**：

| 表 | 权限 | 说明 |
|---|---|---|
| `tutorials` | 公开可读（已发布）/ 仅运营者可写 | 运营者发布的教程，全用户可见；含 cover_url、source_note、status |
| `operator_whitelist` | 仅运营者可读 | 运营者邮箱白名单 |
| `food_records` | 仅本人读写 | 辅食记录（含 images 图片 URL 数组），多设备同步 |
| `baby_profiles` | 仅本人读写 | 宝宝档案（1 人 1 条） |

**本地内置数据**：

| 内容 | 说明 |
|---|---|
| `data/recipes.js` | 36 道内置教程（名称/月龄/封面路径/食材/步骤/贴士/标签） |
| `assets/recipes/*.jpg` | 36 张 AI 封面图，压缩后放分包（≤2MB） |

> 教程库展示 = 内置 36 道 + 云端运营者发布，合并排序。

## 5. 技术方案

| 项  | 方案 |
| -- | --- |
| 框架 | 微信原生小程序（现有初版工程增量改造）+ 独立 PC 管理后台网页 |

| 视频 | V1 不做，数据结构预留 |
| 支付 | V1 无；售卖时接微信支付（需商户号） |

> 备注：开发启动第一步即开通云服务（届时弹窗确认）。数据层统一接口设计，后续升级不重写页面。

## 6. 教程内容运营方案（小红书问题）

**结论：不做爬虫。** 小红书反爬严格、条款禁止抓取，直接爬取不可行且有合规风险。替代路径：

1. **已完成的初始内容**：36 道权威科普来源教程，覆盖 6-24 月龄，内置进小程序开箱即用
2. **运营者发布（V1）**：你刷小红书看到好教程 → **PC 管理后台**整理录入（手机端也可）→ 发布后全用户可见；来源字段选填，引导用自己的话改写
3. **我可持续帮你搜集**：需要扩充教程库时，直接让我按食材/月龄搜集公开资料整理成新条目

> ⚠️ **版权提醒**：教程「全用户可见」属于公开传播，和仅自己收藏不同。① 发布时用自己的话重新整理，不要原样搬运全文和图片；② 来源选填但建议标注；③ 商业化后更要避免大段搬运他人内容。

## 7. 售卖合规清单（V3 前必须完成）

| 事项      | 说明                                                         |
| ------- | ---------------------------------------------------------- |
| 营业执照    | 个体户即可，经营范围含食品销售/制售                                         |
| 食品经营许可证 | 微信小程序「食品」类目硬性要求；自制辅食属散装/现制食品，需确认当地市监部门对家庭制作食品的销售政策         |
| 小程序主体认证 | 企业/个体户主体（个人主体无法开通食品类目）                                     |
| 微信支付商户号 | 绑定同主体商户号后才能收款                                              |
| 建议顺序    | 先跑通 V1（记录+教程+展示）→ 办资质 → 认证主体 → 开通支付 → V2 上线售卖；过渡期可用「微信预订」承接订单 |

## 8. 成本预估（含 PC 管理后台）

**结论：PC 网页管理后台收费不高，整体成本主要在「一次性开发工作量」，日常运行成本很低。**

| 项目 | 成本 | 说明 |
|---|---|---|
| PC 管理后台开发 | 一次性，约等于小程序 2-3 个页面的工作量 | 就是一个登录页 + 教程列表 + 教程编辑表单，无复杂交互 |
| PC 管理后台运行 | **无额外费用** | 与小程序发布在同一个应用/域名下，共用云服务配额，不需要另买服务器和域名 |
| 云服务配额 | 低 | 数据库几万条记录以内、36 张封面（约 2MB）都属轻量；主要增长点是用户上传的记录图片，按 100 个用户 × 每人 50 张 × 500KB ≈ 2.5GB 估算，在配额范围内，超出时按平台配额升级 |
| 微信认证费 | ¥300/年 | 小程序企业/个体户认证（售卖前才需要） |
| 邮箱验证码登录 | 免费自带 | 不用短信，无短信费 |
| AI 封面图生成 | 一次性积分消耗 | 36 张约 180-360 积分（样张已确认风格） |
