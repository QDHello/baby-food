## 0. 背景

宝宝辅食家长的高频痛点是「今天吃什么」——每天打开小程序都要现想、现翻食谱库。二期收藏上线后，宝宝有了自己的"爱吃清单"，但收藏是**平铺列表**，缺少**按天组织**的能力。一周菜单把收藏和月龄适用食谱组织成「7 天 × N 餐」的计划表，一次生成、全天可查，是收藏功能的自然延伸（二期 D20 已预留："一周菜单下期独立需求，本期只打地基"）。

| 编号  | 决策项    | 结论                                            |
| --- | ------ | --------------------------------------------- |
| D30 | 餐次模型   | 按宝宝月龄自动决定餐次数：< 9 月龄 2 餐（午餐+晚餐）；≥ 9 月龄 3 餐（早餐+午餐+晚餐）；加餐本期不做 |
| D31 | 菜池来源   | **收藏优先**：优先从当前宝宝收藏取，不足从「月龄适用食谱池」随机补足；过敏冲突食谱（`recipe.allergens ∩ baby.allergens`）一律排除 |
| D32 | 生成与调整  | 一键生成整周 + 单格「换一换」随机换 + 单格手动指定（弹窗从收藏/适用池选）；手动指定优先级最高 |
| D33 | 去重规则   | 同一周内同一食谱不重复出现（收藏+适用池总数不足 14/21 道时允许重复，但相邻两天不重样） |
| D34 | 存储与周期  | 按**自然周**存储（周一为一周起点），过期周自动失效；本周菜单随时可重新生成/清空 |

## 2. 详细需求

### 2.1 FR-30 一周菜单页

- 入口：「我的」页新增「一周菜单」行（日历图标 📅，排在「我的收藏」「喂养统计」之后）
- 页面结构（自上而下）：
  1. **周标题栏**：「本周菜单 · 11月16日-11月22日」（周一至周日日期范围）+「一键生成」按钮
  2. **餐次说明小字**：如「9月龄 · 每日 3 餐（早/午/晚）」，随宝宝月龄自动变化
  3. **7 天卡片列表**（周一 → 周日纵向排列）：每天一张白卡，卡头「周一 11月16日」（今天高亮主色），卡内按餐次横排格子：餐次名 + 菜名（emoji + 标题）；未安排的格子显示「+ 待安排」虚线占位
- 交互：
  - 点已安排格子 → 底部弹操作单：查看详情 / 换一换 / 手动指定 / 清除
  - 点「+ 待安排」格 → 直接弹手动指定选择弹窗
  - 已过日期（本周内早于今天）的格子置灰不可调整（本周内仍可查看）
- 三态：未设宝宝 → 引导去创建；宝宝 < 6 月龄 → 「满 6 月龄后才有辅食菜单哦」；正常 → 菜单内容（空周 = 每格「+ 待安排」+ 顶部生成引导）

### 2.2 FR-31 一键生成整周菜单

生成算法（服务层 `services/menu.js`，纯本地）：

1. 确定菜池：
   - **收藏池** = `favorites.getFavorites(babyId)` 对应食谱，过滤月龄适用 + 过敏冲突
   - **适用池** = RECIPES 中月龄适用（起始月归属口径：`recipe.minMonths ∈ [stage.min, stage.max)`）且无过敏冲突的食谱，剔除已在收藏池的
2. 餐次骨架：按月龄生成 7 天 × N 餐的空格子序列（D30）
3. 填充：优先用收藏池随机填充；收藏池用尽后从适用池随机补足；遵守 D33 去重（一周不重样优先，池不足时相邻两天不重样）
4. 排序随机化使用时间戳种子，每次生成结果不同
5. 生成成功 toast「本周菜单已生成」；池过小（可用食谱 < 餐次总数）时 toast 提示「收藏和适用食谱较少，部分天数会重复，去收藏更多食谱吧」

### 2.3 FR-32 单格调整

- **换一换**：从菜池中随机换一道（排除当天已有、优先排除本周已用），toast 反馈；无可换时提示「没有更多可换的食谱了」
- **手动指定**：弹窗两 tab——「我的收藏」（收藏列表，复用收藏卡片样式）/「月龄适用」（适用池列表，按起始月归属）；点选即填入该格；弹窗内已在本周用过的食谱显示灰色小标「本周已用」（仍可选，尊重用户意愿）
- **清除**：该格回到「+ 待安排」

### 2.4 FR-33 清空 / 重新生成

- 页面右上「···」或标题栏溢出菜单：清空本周菜单（二次确认 wx.showModal）/ 重新生成（直接覆盖，toast 提示已覆盖）

### 2.5 FR-34 按周持久化与跨周切换

- storage 键 `babyfood_menu_{babyId}`，写入生成周起点；`onShow` 时对比当前自然周，非本周数据自动视为过期 → 展示空周（不删除旧数据，显示「上周菜单已归档，生成新一周菜单吧」提示条）
- 切换宝宝菜单正确隔离（键含 babyId）

### 2.6 FR-35 详情跳转与收藏联动

- 格子菜名点击 → 食谱详情页（现有页面复用）
- 菜单不回写：详情页取消收藏 / 收藏列表取消收藏，**不自动改动**已生成菜单（已排菜单是快照）；重新生成时按新收藏状态计算

**验收标准**

- [ ] 未设宝宝 / <6 月龄进入显示对应引导态，不报错
- [ ] 一键生成后 7 天全部餐次填充完整；宝宝 9 月龄时每天 3 餐、7 月龄时每天 2 餐
- [ ] 过敏冲突食谱不出现在任何格子；收藏的食谱优先出现
- [ ] 一周内同一食谱不重复（池充足时）；手动指定允许重复并正常显示
- [ ] 换一换后旧菜被替换且不出现在当天；清除后格子回到待安排态
- [ ] 杀进程重进菜单不丢失；跨周进入显示空周与归档提示；切换宝宝菜单隔离
- [ ] 格子点击进详情正常返回，菜单内容不变

## 4. 数据结构（本地 storage，阶段 2 上云时映射云端表）

### 4.1 菜单 `babyfood_menu_{babyId}`

```js
// Object，weekStart 为该周周一日期（YYYY-MM-DD）
{
  "weekStart": "2026-11-16",
  "days": {
    "mon": { "lunch": "r12", "dinner": "r5" },
    "tue": { "breakfast": "r33", "lunch": "r7", "dinner": "r15" }
    // ... wed ~ sun；key 为餐次（breakfast/lunch/dinner），值为食谱 id
  }
}
```

- 餐次 key 沿用常量 `MEAL_LABEL` / `MEAL_ORDER`（breakfast/lunch/dinner/snack），本期只用前三者
- 阶段 2 云表 `baby_menus`：id, owner_id, baby_id, week_start, day, meal, recipe_id（一行一格），RLS 本人读写

### 4.2 生成算法

不新增存储，生成逻辑收敛在新增 `services/menu.js`：读取收藏（`favorites.getFavorites`）+ RECIPES + 宝宝档案现算；月龄适用判断与食谱列表页「起始月归属」口径一致，过敏冲突口径与详情页横幅一致（`recipe.allergens ∩ baby.allergens`）。
